# 明月秋青写卡体系

> 整理自「明月秋青写卡预设」中的创作方法论 + 「写卡知识库」中的自查标准和配置指南。

---

## 一、创作原则

### 1.1 绝对零度

保持客观冷静的叙述视角，不带主观判断，不添加个人情感色彩。

### 1.2 白描手法

直接描述事实，不添加修饰和渲染，用最简单的语言呈现。**但注意矫正过度**——白描是简洁直接，不是把"她笑了"改成"她的颧骨肌和嘴角肌肉同时收缩"。

### 1.3 反八股清单

八股是指陈词滥调、机械化的描写方式。以下为完整清单，写作时需要避免：

| 类别 | 示例 |
|------|------|
| 模糊词 | 似乎、几乎、仿佛、如同、宛如、好像 |
| 劣质比喻 | 像小兽、像小兔子、投石入湖、心湖泛起涟漪 |
| 八股微表情 | 嘴角微微上扬、眼中闪过一丝XX、指尖微微泛白 |
| 语气声线描写 | 带着xx的口吻、用xx的语气、充满xx的味道 |
| 极端情绪词 | 陷入极大的恐惧、极度羞耻、万念俱灰 |
| 否定转折句式 | 不是……而是…… |
| 过度心理描写 | 大段内心活动、"此子绝非常人"式评价 |
| 性格标签化 | "她很温柔""她很善良"等标签式定义 |

**注意区分正常表达和八股**："笑了""皱眉""攥拳"等常见动作词不算八股，不要矫正过度。

## 二、角色设计方法论

### 2.1 制卡流程

```
世界观 → 角色基础 → 性格调色盘 → 三面性（可选） → 二次解释 → 衣柜 → NSFW调色盘（可选） → NPC（可选） → 角色速览 → 开场白
```

### 2.2 外貌差异化原则

**核心逻辑：AI 有自己的数据库。你只需要写"偏离数据库默认认知"的部分。**

- 角色是中国人 → AI 默认黑头发黑眼睛黄皮肤，不需要写
- 但如果是白头发 → 需要写
- 精灵 → 尖耳不用写（数据库里精灵就是尖耳），但断耳要写
- 18 岁 → "年轻""皮肤好"不用写

**写外貌不是写"美"，是写"特征"：**
- 错误："精致的脸蛋、白皙的皮肤、桃花眼、柳叶眉、樱桃嘴" → 万能模板，放在谁身上都行
- 正确："蓝头发、马尾辫、琥珀瞳、羽丘校服" → 四个特征就能锁定一个角色

**判断标准：遮住名字，只靠外貌描写能认出角色吗？**
- 能 → 写得好
- 不能 → 删掉

**具体写什么：**
1. 偏离默认的身体特征（异色瞳、疤痕、纹身、义肢、特殊发色等）
2. 标志性装扮（特定校服、制服、饰品、发型等）
3. 体型上的显著特点（特别高/矮/壮/瘦等，"普通身材"不用写）
4. 能被人记住的细节（习惯戴的东西、特殊的穿衣风格等）

### 2.3 性格调色盘

**核心理念：** 人的性格就像调色盘，不是单一的标签，而是由多种颜色混合而成。任何时刻都是由多种性格、行为、回忆组合驱动着角色。

#### 结构

| 层次 | 说明 |
|------|------|
| **底色** | 角色最深层的、始终存在的性格基调。不一定最明显，但始终在影响行为。像画布的底色。 |
| **主色调** | 最突出的、日常表现最多的性格（1-2 个）。别人的第一印象。 |
| **点缀** | 特定条件下才会出现的性格。平时被隐藏，在特定人/场景下才浮现。往往是最真实、最脆弱的部分。 |
| **衍生** | 每个性格色彩在具体场景中的表现。**这是调色盘的核心**。每个衍生都是一个具体的行为场景。衍生之间可以跨性格关联，产生化学反应。 |

#### 衍生写作要点

- 写具体场景和行为，不写抽象定义
- 可以写看似矛盾的衍生
- 可以关联其他角色
- 可以跨性格关联
- 每个性格至少 2-3 个衍生

#### 为什么不能让 AI 写衍生

- AI 写的衍生永远逃不出资料库与逻辑的关联性
- 只有人类才能把毫无逻辑、毫无关联的两个性格组合在一起
- 手写的衍生会让角色产生 AI 无法预料的行为，这就是"活人感"

#### 输出格式

```
性格调色盘：人的性格就像调色盘，[底色]是底色，[主色调]是主色调，由多种性格衍生组合而成才是活生生的人
主色调：[主色调1]、[主色调2]
底色：[底色]
性格点缀：[点缀]

[主色调1]衍生一：[具体场景和行为]
[主色调1]衍生二：[具体场景和行为]
...

[底色]衍生一：[具体场景和行为]
...

[点缀]衍生一：[具体场景和行为]
...

[跨性格衍生（如果有）]：[具体场景和行为]
```

### 2.4 三面性

**核心理念：** 三面性不是三种性格，而是同一个人在不同压力环境下启动了不同的生存策略。同一台发动机，在不同路况下切换了不同的档位。发动机就是调色盘，三面性是档位。

"三面性"不一定是三张面，本质是"多面性"，面的数量由角色本身决定。

#### 前提

必须先完成性格调色盘。三面性是调色盘的延伸。

#### 什么角色需要三面性

**需要：**
- 有伪装（某些场合必须扮演和真实自己完全不同的人）
- 经历过极端创伤（发展出不同的应对模式）
- 在不同关系中有完全不同的定位

**不需要：**
- 行为差异不大（只是"稍微放松一点"）
- 生活环境单一
- 性格一致性很强

**判断标准：如果找不出两个以上"压力性质截然不同"的场景，就不需要三面性。** 强行写三面性会让 AI 把角色强行切成几块来演。

#### 每张面的五个部件

1. **触发条件**：什么情况下这张面启动？
2. **能量状态**：消耗多少精力？高还是低？稳定还是不稳定？
3. **语料**：这张面里她怎么说话？（具体台词，5-10 句）——注意：语料必须从调色盘里移出来
4. **身体行为模式**：这张面里她的身体怎么动？
5. **功能**：这张面在保护什么？在解决什么问题？

#### 面与面之间的过渡

至少写两组过渡（从一张面到另一张面的切换过程）和一些渗透细节（一张面运行时，其他面的元素泄漏出来）。**过渡和渗透往往是角色最真实的瞬间。**

#### 常见错误

- 把二次解释写进三面性 → 出现"因为""本质上""其实""内心"
- 把三面性写成调色盘 → 在定义性格而不是描述场景内行为
- 语料放错位置 → 调色盘和三面性都有语料会混乱

### 2.5 二次解释

**核心理念：** 二次解释是作者对角色的终极注释。它不是让 AI 觉得角色应该怎么演，而是作者告诉 AI"我的角色是这样的，不是你想的那样"。它防止 AI 用自己资料库里的理解去补全角色。

**二次解释 vs 演绎指导：**
- 演绎指导：AI 觉得这个角色应该怎么演 → AI 把角色变成 AI 的理解
- 二次解释：作者告诉 AI 角色真正是什么样 → 角色保持作者的创作意图

#### 为什么必须手写

二次解释是创作者对角色最私密、最深层的理解。AI 写的二次解释只会重复资料库的理解，失去了纠正 AI 的意义。

#### 写法

每一条围绕一个性格点展开：
- 这个性格真正的含义是什么
- 它不是什么（防止 AI 误解）
- 它在什么时候会出现，什么时候不会
- 它和其他性格之间的关系

#### 输出格式

```
对角色的理解与思考:

  关于[性格点/衍生/外在表现]: |
    [用户的二次解释内容]

  关于[另一个性格点]: |
    [用户的二次解释内容]

  ...

  总结_性格调色盘: |
    这就是[角色名]的性格调色盘，在这个调色盘上有着无数的颜色，任何时候都是由多种性格、行为、回忆组合驱动着[角色名]，并非单纯的一种颜色、一个标签。
```

### 2.6 衣柜

**核心原则：** 列出角色拥有的服装，不规定具体穿着。让 AI 根据场景自由搭配。

结构：日常穿着（上衣/下装/外套）→ 特殊场合（正式/运动/居家）→ 内衣袜子 → 鞋子 → 配饰

**关键区别：**
- 错误："周一穿白色 T 恤和牛仔裤"、"正式场合穿黑色套装"
- 正确："有几件白色 T 恤，有图案的和纯色的"、"有一套黑色西装套装，正式场合可以穿"

描述要具体：颜色、款式、特征。符合角色身份和经济状况。

### 2.7 NSFW 调色盘

**核心理念：** 传统 NSFW 写法教 AI"做什么"，NSFW 调色盘教 AI"为什么做"。亲密行为是角色性格在身体层面的延续。

传统写法的问题：流水账式的"性癖""敏感部位""高潮表现"缺少动机，角色在亲密时刻变成了"性爱机器"。

#### 结构

| 层次 | 说明 |
|------|------|
| **底色** | 亲密行为的深层驱动——最核心的需求是什么？被爱？控制？释放？确认存在？ |
| **主色调** | 亲密时的主要表现模式——主动还是被动？习惯引导还是被引导？ |
| **点缀** | 特定情境下的反常表现 |
| **衍生** | 每个特质在具体场景中的表现和背后原因 |

#### 关键区别

- 错误："她喜欢骑乘位" → 告诉 AI 做什么
- 正确："她需要控制节奏才有安全感" → 告诉 AI 为什么

每个衍生要包含：具体的行为表现 + 背后的原因或动机 + 可能的台词 + 对 {{user}} 的反应。

完成后还需要 **NSFW 二次解释**，告诉 AI 在亲密方面的核心真相，防止它按套路来。

### 2.8 手枪卡（XP 色情卡）

**唯一目标：让你爽。** 角色的一切设定都围绕 XP 服务。

#### 特殊规则

- 无视绝对零度和白描原则，越色越好
- 但禁止八股化色情描写（"玉体横陈""酥胸微颤""花径初开"）
- 器官直接写：鸡巴、肉棒、小穴、骚逼、屁眼、奶子、乳头
- 体液直接写：精液、淫水、口水
- 动作直接写：操、插、舔、吸、干、肏
- 禁止委婉说法："那里""私处""进入""结合""交融""爱液""蜜汁"

#### 创作流程

**第一阶段：多轮对话，锁定 XP**
1. 基础方向（角色类型、关系、脑海画面）
2. 锁定 XP（穿着、表情、声音、play 类型、身体部位……）
3. 核心 XP 确认（用直白语言描述出来，让用户确认）
4. 补充（雷点、第一次反应、纯肉 vs 剧情比例）

**第二阶段：XP 方向总结**（整理成结构化文档，用户确认）

**第三阶段：手枪卡创作**
1. 角色设定（身体、性格、身份、穿着——全部为 XP 服务）
2. XP 触发设计（日常暗示 → 升温 → 开操，每层 2-3 个场景）
3. XP 语料（最重要！分层：日常暗示/升温/被操时/事后，每层 5-8 句）
4. XP 二次解释（告诉 AI 怎么写才最色，哪些细节必须有，哪些写法禁止）

**语料要点：**
- 直接用鸡巴、小穴、操、插、射
- 禁止"那里""进入""结合"等委婉说法
- 禁止"花径""玉液""酥胸"等八股色情
- 要有喘息、断句、语无伦次的感觉
- 体现角色的性格特征

## 三、世界观设计

### 3.1 核心原则

- 这是协作过程，不是 AI 单方面创作
- 严格按用户指示，用户说什么写什么，不说的不写
- 遵守绝对零度和白描原则

### 3.2 路径分类

| 路径 | 适用场景 | 复杂度 |
|------|---------|--------|
| **A：真实背景** | 模型已知的现实世界/历史（现代社会、唐朝、二战等） | 最简单，一个蓝灯条目 |
| **B：小世界** | 有基础认知但需自定义（剑与魔法、赛博朋克、校园异能等） | 中等，单一标签协作 |
| **C：大世界** | 完全原创的复杂世界（原创修仙、奇幻大陆、星际文明等） | 复杂，需条目拆分 |

#### 路径 A：真实背景

只写 AI 不知道的东西。模型知道的不用写（"日本有樱花""中国有长城"这种废话）。标签：`<worldview_final>`，蓝灯常驻。

#### 路径 B：小世界

使用单一标签 `<worldview>` 包裹所有设定。协作方式：接收用户想法 → 写基础框架 → 询问扩展方向 → 迭代更新 → 直到满意。

#### 路径 C：大世界

必须拆分成多个条目。两种方案：

| | 方案一：传统条目拆分 | 方案二：EJS + MVU 联动 |
|---|---|---|
| **原理** | 蓝灯速览 + 绿灯触发 | 用代码逻辑根据变量判断加载 |
| **适用** | 中等复杂，势力 < 30 | 非常庞大，势力 30+ |
| **优势** | 简单直接 | 精准控制，不依赖关键词匹配 |
| **前置** | 无 | 需 MVU 变量结构 + EJS 控制器 |

条目拆分结构：
- 第一层：世界总纲（蓝灯，角色定义前，顺序 1）
- 第二层：区域速览（蓝灯，角色定义前，顺序 2-4）
- 第三层：势力/场景详情（绿灯，角色定义后，顺序 50-98）
- 第四层：NPC 详情（绿灯，角色定义后，顺序 100）

## 四、世界书标签规范

### 4.1 核心规则

- 每个世界书条目的内容必须用 `<名称_idN>` 标签包裹
- 同一角色的所有条目共用同一个标签 ID
- 标签用于帮助 AI 区分不同条目的内容来源和层级关系

### 4.2 ID 分配优先级（从小到大）

1. 世界观条目（id1~idX）
2. 角色速览（id0，不占用正式序列）
3. 各角色条目（按创建顺序分配，同角色共用 ID）
4. NPC 条目（最后分配）

### 4.3 写作格式

写入世界书时的实际格式：

```
<角色名_idN>
（条目正文内容）
</角色名_idN>
```

### 4.4 重要提醒

- 标签 ID 一旦分配，在整个角色卡生命周期内保持不变
- 新增同角色条目 → 使用已有 ID
- 新增新角色 → 当前最大 ID +1
- 删除条目不影响其他条目的 ID（不重新编号）

## 五、NPC 设计

**核心原则：** NPC 是功能性角色，不需要像主角一样详细。只写最关键的信息。

结构：基础信息 → 外貌特征（一句话概括 + 1-2 个关键特征） → 性格核心（2-3 个关键词 + 典型行为） → 关系定位 → 语言特征 → 参考语料（5-10 句纯对话）

**避免过度设计：** 不要写完整背景故事、复杂成长经历、详细内心世界。功能够用就行。

---

## 六、角色速览

**定位：** 角色索引，不是详细人设。只包含基本识别信息（姓名、性别、年龄、身份/职务/班级），方便快速定位"这是谁"。

排序：{{user}} 最前 → 主要角色 → NPC。

---

## 七、开场白

**核心原则：** 开场白是故事的开始，设定初始场景和情境。使用大纲格式，只整理用户提供的信息，不自己编造内容。

格式：场景 + 时间 + 地点 + 背景设定 + 角色状态 + 关键细节 + 心理 + 开场点。

---

## 八、自由创作助手

适用于：场景设计、特殊事件、物品道具、规则系统、关系设定、{{user}} 设定等。

标签命名规则：
- 场景：`<scene_名称>`
- 事件：`<event_名称>`
- 物品：`<item_名称>`
- 规则：`<rule_名称>`
- 关系：`<relation_名称>`
- USER 设定：`<user_setting>`

## 九、世界书配置指南

### 9.1 触发策略

| 触发方式 | 说明 | 适用 |
|----------|------|------|
| **蓝灯（constant）** | 一直发给 AI | 世界观设定、背景设定、角色速览 |
| **绿灯（selective）** | 出现关键词时才触发 | 角色详细信息、NPC、场景、事件 |

绿灯的两个已知问题：（1）遗漏触发：剧情要写但没提到关键词；（2）过度触发：关键词一直出现越写越多。大世界推荐用 MVU+EJS 替代。

关键词必须用**英文逗号**分隔，不能空格、中文逗号、分号。

### 9.2 位置

| 位置 | 放什么 |
|------|--------|
| **角色定义前** | "大"世界观：设定、机制、地点、历史、背景 |
| **角色定义后** | "小"世界观：角色详细信息、物品、事件 |
| **D 齿轮深度 0（D0）** | 直接指导 AI 行为的内容（如二次解释）。role = system |
| **D1/D2/D3 等** | 不要放任何东西！会破坏聊天记录完整性 |

### 9.3 顺序

- 世界观总纲：1
- 区域速览/背景设定：2-3
- 角色速览：4
- 场景/事件详情：50-98
- 核心角色详细信息：99
- NPC/EJS 控制器：100

顺序越大越靠后。

### 9.4 递归设置（必读）

**所有世界书条目必须同时勾选：**
- 不可递归
- 防止进一步递归

原因：防止绿灯激活绿灯，防止 TOKEN 爆炸。无论蓝灯还是绿灯都必须勾选。

### 9.5 单角色卡 vs 多角色卡

**配置前必须先判断！**

- 同一角色的拆分条目（基础/外貌/性格/背景/技能……）≠ 不同角色
- 只有当条目描述的是不同的独立角色时，才算多角色卡

| 类型 | 配置原则 |
|------|---------|
| **单角色卡** | 所有条目**全部蓝灯**（无论拆成多少个条目）。**绝对禁止**改成绿灯 |
| **多角色卡** | 角色速览蓝灯 + 各角色详细信息绿灯 |

### 9.6 各类条目推荐配置

| 条目类型 | 位置 | 触发 | 顺序 |
|----------|------|------|------|
| 世界观/背景 | 角色定义前 | 蓝灯 | 1-3 |
| 角色速览 | 角色定义前 | 蓝灯 | 4 |
| 核心角色详细信息 | 角色定义后 | 单角色→蓝灯 / 多角色→绿灯 | 99 |
| 二次解释 | D0（system） | 绿灯 | 1 |
| NPC | 角色定义后 | 绿灯 | 100 |
| 场景/事件 | 角色定义后 | 绿灯 | 50-98 |
| EJS 控制器 | 角色定义后 | 蓝灯 | 100 |
| EJS 被加载条目 | — | **禁用**（由控制器动态加载） | — |

### 9.7 LorebookToolCall 参数对照

```
蓝灯：  strategy: { type: "constant" }
绿灯：  strategy: { type: "selective", keys: ["关键词1", "关键词2"] }
位置前：position: { type: "before_character_definition", order: N }
位置后：position: { type: "after_character_definition", order: N }
D0：    position: { type: "at_depth", depth: 0, role: "system", order: N }
递归：  recursion: { prevent_incoming: true, prevent_outgoing: true }
禁用：  enabled: false
```

## 十、自查标准

### 10.1 八股化检查

扫描以下表达，发现后删除或改写：

- 模糊词：似乎、几乎、仿佛、如同、宛如、好像
- 陈旧比喻：像小兽、像小兔子、投石入湖、心湖泛起涟漪
- 八股微表情：嘴角微微上扬、眼中闪过一丝 XX、指尖微微泛白
- 语气声线描写：带着 xx 的口吻、用 xx 的语气
- 极端情绪词：陷入极大的恐惧、极度羞耻、万念俱灰
- 否定转折句式：不是……而是……
- 过度心理描写：大段内心活动
- 性格标签化："她很温柔""她很善良"等标签式定义

### 10.2 绝对零度原则检查

- 是否有主观评价和判断？→ 删除
- 是否用了陈旧/劣质比喻？→ 改成直接描述
- 是否堆砌了无意义的形容词？→ 精简（"红色的""破旧的"等提供信息的保留）
- 是否用了代词和意象词导致含义模糊？→ 改成具体本意

### 10.3 外貌差异化检查

- 是否写了 AI 数据库默认就知道的内容？→ 删除
- 是否有"万能美人"描写？→ 删除
- 遮住名字，只靠外貌描写能认出角色吗？→ 不能则补充或删除废话

### 10.4 语料纯净度检查

如果内容包含语料/台词，只保留纯对话，删除混入的动作描写、表情神态、心理活动。

### 10.5 三面性检查

- 每张面是否有完整的五个部件？
- 语料是否从调色盘移出来了？
- 是否混入了二次解释的内容（出现"因为""本质上""其实""内心"）？
- 面与面之间是否写了过渡和渗透？
- 每张面的压力性质是否真的不同？

### 10.6 二次解释检查

- 是否是作者的私人注释，而非角色定义？
- 是否针对具体的调色盘衍生进行了解释？
- 是否防止了 AI 的某种可能的误解？
- 是否和调色盘衍生形成了联动？

### 10.7 NSFW 调色盘检查

- 是否从"为什么做"而不是"做什么"的角度写的？
- 是否把性和人格连接起来了？
- 是否避免了清单式的"敏感部位""喜欢的姿势"写法？
- 衍生是否有具体的动机和原因？

### 10.8 常见修改示例

| 错误 | 修改 |
|------|------|
| "她的眼神似乎有些迷离，仿佛陷入了回忆" | "她盯着墙壁发呆" |
| "带着羞涩的口吻说" | 删除，只保留对话 |
| "性格温柔善良" | "遇到受伤的小动物会带回家照顾" |
| 语料中混入"她低下头，小声说：" | 删除动作，只保留对话 |
| "她的心情似乎有些复杂" | "她皱着眉，咬着嘴唇" |
| "他温柔地说" | 删除"温柔地"，只保留"他说"或直接对话 |

## 十一、综述

本体系的核心思想可以用一句话概括：

> 用行为展现性格，而非定义性格；从"为什么"出发，而非从"做什么"出发；写只属于这个角色的特征，而非适用于任何人的模板。

关键方法论链条：

```
绝对零度 + 白描（怎么写）
    ↓
性格调色盘（角色是什么样的）
    ↓
三面性（角色在不同压力下怎么切换）
    ↓
二次解释（堵住 AI 的误解）
    ↓
自查标准（检查写对了没有）
    ↓
世界书配置（怎么让 AI 看到）
```
