# 知识库 tool 注入

把世界书知识伪装成 AI 的"工具查询结果",让 AI 分清:**这是查到的知识,不是用户说的话。**

比如世界书写了"北京零下 120 度",普通世界书里 AI 当设定、可能忽略;伪装成 tool 返回后,AI 会当成刚查到的数据老老实实引用,绝不和用户输入混淆。

## 原理

条目标题加 `_知识库` 前缀 + 位置设 Outlet + 锚点名称(出口名)填 `_知识库` → 脚本收集被激活的条目 → 发送前在 chat 里伪造 `assistant tool_calls` + `tool` 返回消息对。对 AI 来说就像它真的查了个知识库。

## 安装

酒馆助手 → 脚本库 → 导入 `酒馆助手脚本-知识库tool注入.json` → 启用。脚本 ID 固定,更新时重新导入即可覆盖。

## 配置(5 步)

举个例子:你想把"北京今日气温"做成 AI 可查询的知识。

1. 条目标题改为 `_知识库_北京温度`(前缀 `_知识库` 不能少)
2. 条目位置设为 **Outlet**,此时会出现"锚点名称(出口名)"输入框,填 `_知识库` —— **必须填,否则条目不会被收集**
3. 预设里**不要**放 `{{outlet::_知识库}}` 宏
4. 预设"提示词后处理类型"设为 `NONE` / `MERGE_TOOLS` / `SEMI_TOOLS` / `STRICT_TOOLS`
5. 后端必须是 **Chat Completion**(OpenAI 官方或兼容)

搞定后在扩展设置区"知识库 tool 注入"面板点**校验配置**,有问题会直接告诉你。

## 适合放什么

✅ 名词解释、角色档案、数据表 —— 一切"AI 该当数据查"的内容
❌ 世界观规则、写作风格 —— 这些该放普通世界书,AI 才会当设定遵守

判断标准:**"AI 要遵守的设定"用普通世界书,"AI 要查询的数据"用 _知识库。**

## 注意

- 蓝灯条目每轮都注入、不省 token;要按需注入用绿灯 + 关键字
- 注入内容在 chat 尾部,不吃上下文缓存;常驻知识放普通世界书更省钱
- 仅支持 Chat Completion 后端
